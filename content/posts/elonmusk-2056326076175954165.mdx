Yeah, /implement is easily my #1 skill.

It’s not just the implement → review → fix loop that gives way better output — it also has a built-in memory system.

After each task, the orchestrator summarises the issues that were fixed, saves them to a persistent file of “most common problems,” and on the next run injects that knowledge into the implementer + reviewer prompts so they avoid repeating the same mistakes.

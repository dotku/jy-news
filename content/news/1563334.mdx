根据 OpenAI 开发者团队在社交平台 X 上发布的示例截图，锁定的 Mac 会显示一层“Codex 正在使用你的 Mac”的覆盖提示，并提示用户按任意键或点击以解锁设备。

要启用该功能，用户需要安装 Computer Use 插件，并在系统设置中授予其“屏幕录制”和“辅助功能”权限。 完成设置后，Codex 便可以在用户明确授权的应用内执行点击窗口、输入文字、导航菜单以及访问剪贴板等操作，模拟人工在图形界面中的常规使用行为。 OpenAI 表示，这一能力主要面向那些命令行工具难以覆盖的使用场景，例如重现只在图形界面中出现的 bug、调整应用设置，或在 Codex 正协助开发的桌面应用中运行特定流程等。

在安全与权限控制方面，Codex 在首次接管每一款新应用前都会先征得用户同意，用户也可以选择对特定应用设置为“始终允许”，以减少重复确认操作。 OpenAI 同时强调，该功能在推出初期暂不向欧洲经济区、英国及瑞士用户开放，且无法用于自动化终端（Terminal）应用、Codex 自身应用以及系统层面的管理员权限提示窗口。 这一限制反映了在强化自动化与远程操作能力的同时，OpenAI 仍需在合规及安全边界方面进行区域性权衡。

此次更新还延续了 Codex 近期的一系列功能扩展，包括新上线的“Appshots”功能以及“/goal 模式”等。 其中，Appshots 允许用户通过双击 Command 键（Command-Command 快捷键），一键将当前 Mac 应用窗口的截图和相关文本内容注入到 Codex 对话中，以便智能体理解界面上下文并给出针对性操作或建议。 而 /goal 模式则支持 Codex 围绕某个明确目标持续工作数小时甚至数天，使其在编码代理、桌面操作自动化以及长周期任务推进等场景中具备更强的持续性和规划能力。

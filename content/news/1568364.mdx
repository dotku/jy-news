根据苹果支持页面的提示，这一变更将影响所有使用加密 Mac OS 扩展格式的 Mac 用户，苹果要求相关用户尽快检查并确认自己磁盘的文件系统与加密状态，以免在升级到 macOS 28 后遭遇数据访问中断。 实际上，自 macOS 26 起，系统就已对仍在使用加密 HFS+ 的用户发出预警，如今则进一步明确了停用时间表。

需要强调的是，这次变更专门针对“加密且为 Mac OS 扩展格式”的磁盘宗卷；如果磁盘只是使用 Mac OS 扩展但未启用加密，现阶段仍可正常工作。 即便如此，业内普遍认为，这已是 HFS+ 走向终点的又一“倒计时”，提示用户尽早迁移至 APFS，以获得更好的兼容性与长期支持。

苹果建议用户首先通过“磁盘工具”检查磁盘格式和加密状态。 用户可打开“磁盘工具”，在菜单栏“显示”中选择“只显示宗卷”，然后在侧边栏选中目标宗卷，在右侧查看格式信息：若同时出现“Mac OS Extended”和“Encrypted”标记，则说明该盘属于受影响的加密 HFS+，需要采取进一步措施。 若只具备其中之一，例如仅为加密 APFS 或仅为未加密 HFS+，则暂不在本次调整之列。

针对已经确认为加密 Mac OS 扩展的磁盘，苹果提出了两条主要解决路径：一是重新格式化为 APFS 或 APFS（加密），二是先取消加密，再将 HFS+ 转换为 APFS。 重新格式化是更为彻底的做法，但会清除磁盘上全部数据，因此在操作前必须确保有完整可靠的备份。

若选择重新格式化，用户需要在“磁盘工具”中选中目标宗卷，点击带“X”标记的擦除图标，在“方案”弹出菜单中选择 GUID 分区图（GUID Partition Map），再在“格式”中选择 APFS 或 APFS（加密）并输入新名称后执行“抹掉”。 这将使磁盘完全转为新文件系统，适配后续的 macOS 版本，同时确保未来在 APFS 环境下的读写与加密功能均能获得官方支持。

另一种做法是先移除加密，将磁盘转换为未加密的 Mac OS 扩展格式，再在保留数据的前提下将其升级为 APFS。 在这条路径下，用户需连接目标磁盘，输入加密密码解锁后，在桌面上对磁盘图标执行“控制键+点击”，选择“解密”，并再次输入密码以确认操作。 完成后，磁盘仍为 HFS+ 格式，但不再加密，可继续在系统中访问。

随后，用户可再次打开“磁盘工具”，通过“显示”菜单选择“只显示宗卷”，在侧边栏选中该宗卷后，打开“编辑”菜单并选择“转换为 APFS”，确认转换即可在不抹除数据的情况下完成文件系统升级。 若用户希望在新的 APFS 宗卷上重新启用加密，可在桌面上控制键点击磁盘图标，选择“加密”，并按照系统引导设置密码与相关选项。 需要注意的是，苹果警告，此类“解密再转换”的方式并不适用于加密的 Time Machine 备份磁盘，这类备份盘在迁移方案上需另行规划。

除了具体操作指南外，这次调整也再次凸显苹果在文件系统演进上的长期路线图。 Mac OS 扩展格式最早于 1998 年随 Mac OS 8.1 推出，用以取代更早的分层文件系统 HFS，因此也被称为 HFS+。 在之后的多年中，苹果不断为 HFS+ 添加诸如日志记录等功能，但在同一技术架构上反复加装“补丁”终究存在局限，因此苹果最终选择开启新一代文件系统的设计。

2016 年，苹果发布了 Apple 文件系统（APFS），并在 2017 年将其设为 Mac 设备的默认磁盘格式。 相较 Mac OS 扩展，APFS 在性能、安全性以及现代存储特性方面均有所提升，并成为如今 macOS 与 iOS 设备的统一文件系统基础。 加密 HFS+ 被正式宣告退出支持序列，正是这一演变过程中的节点之一，提醒仍在使用旧格式的用户尽快完成迁移。

对于未加密的 Mac OS 扩展磁盘用户而言，本次政策暂未直接造成影响，但文章指出，这一群体也不应掉以轻心，应主动规划向 APFS 的过渡。 随着苹果持续推动新技术栈，旧格式的支持窗口迟早会关闭，提前完成转换既可减少未来升级风险，也能享受 APFS 带来的性能与安全优势。 正如报道所言，在苹果逐步淘汰加密 HFS+ 之后，迟早有一天，“苹果也会来找你”。

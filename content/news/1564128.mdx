在当前正式版的 Windows 11 中，系统默认不允许多个应用同时访问摄像头，例如当用户先后打开 Microsoft Teams 与 Zoom 时，只有最先启动的应用能够获得摄像头权限，后启动的应用将无法调用摄像头视频流。 这也意味着，如果用户在使用 Teams 进行视频会议的同时，尝试通过 OBS 等软件录制自己的画面，OBS 将无法获取摄像头图像。

微软官方错误提示中也曾明确要求用户“关闭其他正在使用摄像头的应用”，否则系统会给出 0xC00D3704 等错误代码，提示摄像头已被其他程序占用。 在作者给出的示例中，当浏览器访问在线摄像头测试工具并调用设备摄像头后，再打开系统自带的“相机”应用，后者就无法访问摄像头硬件，并弹出相关报错信息。

随着 KB5089573（内部版本 26200.8524 及更高版本）的发布，这一延续多年的限制终于被移除，支持多应用共享摄像头的新模式开始向用户开放。 在启用该功能后，只要满足硬件性能和驱动条件，多个应用可以在同一时间并行访问摄像头，不再需要频繁关闭前一个应用来腾出摄像头资源。

如果用户更新到 KB5089573 后发现多应用模式没有自动生效，还需要在设置中手动开启这一新功能。 微软提供的路径为：设置 > 蓝牙和设备 > 摄像头，选择正在使用的摄像头设备后向下滚动，在“高级设置”中点击“编辑”，再打开“允许多个应用使用你的摄像头”的开关。

除了多应用摄像头模式外，本次更新还带来了另一个与摄像头体验相关的重要改动——名为“基本摄像头”（Basic Camera）的新功能。 微软此前在确认将推出一次面向 Windows 11 的重大更新时曾表示，将重点提升系统在文件资源管理器、Copilot 等多个方面的表现，同时也会改善摄像头与音频设备的可靠性。

微软坦言，部分用户在会议或日常使用中会遇到摄像头“消失”或随机失效的问题，音频设备（包括麦克风与扬声器）也时常出现无法正常工作的情况。 微软认为，许多摄像头相关问题的根源在于设备厂商驱动，而非 Windows 更新本身。 文章作者也举例称，其所使用的 HP Spectre 设备曾出现摄像头一夜之间从系统中消失的情况，起初怀疑是 Windows 更新所致，但在重新安装 HP 提供的摄像头驱动后才确认问题出在 OEM 端。

为帮助用户快速判断故障归因，本次 KB5089573 更新引入的“基本摄像头”功能允许系统在出现问题时回退到微软自带的基础驱动及默认设置来驱动摄像头。 当用户开启“基本摄像头”并发现摄像头在该模式下可以正常工作时，就可以大致确定问题是由 OEM 驱动或其附带软件导致，而不是 Windows 系统本身出现了严重错误或硬件完全损坏。

报道指出，多应用摄像头模式与“基本摄像头”功能将与其他若干改进一同逐步推送给用户，包括安装流程中更易理解的用户文件夹命名方式，以及面向性能的“低延迟配置文件”选项等。 其中，新的用户文件夹命名方案旨在解决过去 Windows 11 安装时默认生成难以辨认的 5 字母用户目录名称的问题，而“低延迟配置文件”则可在部分设备上优化 CPU 响应速度，提升系统流畅度。

总体来看，微软正在通过此次更新系统性地改进 Windows 11 在视频会议、内容创作等高频使用场景下的体验。 多应用摄像头模式的开放有望惠及需要同时录制、直播和视频会议的专业与普通用户，而“基本摄像头”功能则为排查故障提供了更直观的路径，有助于区分是系统更新还是硬件厂商驱动造成的问题。

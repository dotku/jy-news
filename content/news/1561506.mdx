然而，当微软 Windows Shell 负责人 Tali Roth 在 X 上发文，庆祝团队兑现这一批性能更新承诺时，却重新点燃了关于 Windows 11 文件资源管理器的老话题。不少用户对当前启动速度的改善持怀疑态度，认为微软通过“预加载”文件资源管理器来加快启动，只是浪费系统资源的权宜之计，而不是从根源优化这款老牌应用的底层代码。

在连续的讨论中，Roth 罕见地公开阐述了微软针对这一“长期顽疾”所采取的多层次改造思路。她承认，许多用户在使用 Windows 11 时，会明显感觉文件资源管理器比 Windows 10 时代更慢，这很大程度上源于微软在古老的 Win32 基础之上叠加了 XAML、WinUI 3 等现代 UI 框架，导致混合架构带来额外性能开销。

为缓解启动迟缓的问题，微软此前在 Windows 11 中引入了“后台预加载”机制：系统会在用户点击之前，将资源管理器相关组件预先缓存到内存里，理论上可以实现几乎“秒开”的体验。但实测显示，这一机制会额外占用约 35MB 内存。对于现代 PC 而言，这个数字并不算高，但用户真正不满的是——预加载只改善了首次启动，进入应用后，文件夹导航、缩略图渲染、右键菜单弹出等操作依然显得沉重而拖沓。

正因如此，一部分高阶用户选择转向第三方工具，例如 File Pilot。根据测试，这类替代文件管理器可以在不依赖激进后台缓存的前提下实现瞬间启动与流畅导航，证明通过更高效的实现完全有可能规避目前 Windows 11 官方资源管理器的性能包袱。

面对“预加载只是粗暴投机取巧”的质疑，Tali Roth 在 X 上回应称，微软并不是在两种路径之间做二选一。“就像很多问题一样，答案是‘并且（AND）’。”她表示，微软现在是从整体视角来审视启动性能，采用多种手段叠加，以确保用户在最常访问的区域都能获得足够敏捷的响应。预加载关键组件，只是整个组合拳中的一招。

更重要的是，Roth 明确强调，真正的底层优化工作正在同步推进。她列出了 Windows Shell 团队当前正在实施的几类工程改进，包括：针对启动流程的精细优化，通过调整加载顺序、加速关键路径调用来缩短冷启动时间；主动削减“臃肿”逻辑，移除不必要的后台工作与视觉动画，降低感知延迟；实施更深层的基础性修正，从根本上减少多余的磁盘读取并降低各种卡顿场景出现的概率。

这些架构层面的改造，有望缓解预加载无法触及的“应用内迟缓”问题。比如，减少不必要的磁盘访问，直接影响到用户点击某个目录后，文件列表填充完成的速度，这类体验提升是单靠预加载无法实现的。

Roth 表示，这些基础性优化会在接下来数月内以增量形式逐步推送。目前，从最新的 Windows Insider 测试版本中，已经能看到部分成果：例如在深色模式下，文件资源管理器中恼人的“白屏闪烁”现象被移除，整体导航体验也变得更为顺畅。同时，那些可以追溯到 Windows 95 时代的老旧“属性”对话框，也正在被新的 WinUI 3 风格、支持深色模式的现代界面所取代，显示出微软在 UI 与基础框架上的系统性更新决心。

对外界而言，微软此次在文件资源管理器性能问题上罕见地选择更高程度的透明态度，某种程度上算是一种积极信号：公司并未打算单纯依靠“多占点内存”来掩盖混合框架带来的性能损耗，而是承认问题复杂度，并尝试以预加载与底层瘦身并行的方式解决。若微软最终能成功将智能预加载与更精简、更高效的代码结合起来，Windows 11 的文件资源管理器或许有机会在体验上真正超越 Windows 10。

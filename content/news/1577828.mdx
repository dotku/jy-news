右侧窗口支持扩展到超过屏幕一半的大小，且跟我们日常使用的Chrome等浏览器一样支持多标签页显示，网页翻译、查找、全屏显示、分享、收藏等，堪称一个“微信浏览器”的雏形。

特别值得一提的是，目前微信生态最重要的内容形式之一“小程序”的展示目前依然采取独立窗格形式，暂未调用官方内置浏览器。

你可能会说，这是一个很小的改动。过去很多年在微信点击链接等也都会调用微信自有浏览器展示。对于腾讯来说，姑且不说其很早就有QQ浏览器等布局，后来还收购了搜狗，浏览器这点技术就是小菜一碟。但雷科技认为，真正值得关注的是：为什么微信要采取这种分栏显示模式？雷科技认为，其本质是在进一步将浏览器内置到微信内。

为什么要这样改？答案可能是：Agent。浏览器是Agent操控与交互的关键形态，AI都在内置浏览器。微信是用户生活、工作都离不开的平台，未来会加速跟Agent融合成为腾讯的超级AI入口，这一次小改动算是给Agent化铺路。

如果你有持续关注AI和Agent动态应该会发现，浏览器这一看似最古老的应用形态，早已成为AI巨头们绕不过的事情。

01

OpenAI的AI浏览器探索：

从独立到整合

2025 年 10 月，OpenAI 发布 ChatGPT Atlas 时，Sam Altman 将其形容为一次重新思考浏览器的机会。不过前阵子，OpenAI 宣布停止这款浏览器的服务，并提醒用户导出书签、保存网页。它给出的说法是 Atlas 的浏览器 Agent 能力，将被转移到 ChatGPT 和 Codex。

一款被寄予厚望的 AI 浏览器，就这样消失了。

坦白讲，这个结果并不太让人意外。Atlas 发布时，雷科技也曾一度认为，浏览器是最适合承载 Agent 的产品形态。浏览器有用户打开的网页、登录状态、历史记录和私人信息，Agent 不只知道人正在看什么，也能直接点击、输入和提交。

图片来源：OpenAI

问题是，通用 Agent 产品进化得比浏览器快。OpenAI 关闭了 Atlas，但 Codex 早早集成了浏览器，也合并到了新的 ChatGPT 桌面端上。浏览器仍然存在，却不再需要一个独立客户端。

所以，其他 AI 浏览器呢？

02

AI盯上浏览器，

直到能自己上网的Agent爆发

如果把时间拨回三年前，AI 浏览器还只是浏览器旁边多出来的一块侧边栏。

2023 年，微软将 Copilot 放进 Edge，Opera 推出 Aria，Arc 也用生成式 AI 整理标签页、重命名文件和生成摘要。它们确实省下了一些复制、粘贴和切换窗口的动作，但大部分功能都能被一个插件替代。浏览器还是浏览器，AI 更像住在侧边栏里的问答助手。

到了 2025 年，Dia、Comet（Perplexity 旗下） 接连出现，行业开始认真谈论原生 AI 浏览器。AI 不只读取当前页面，还能理解多个标签页、浏览历史和用户账号，再围绕一项任务组织信息。浏览器第一次有机会摆脱网页浏览的角色，成为一个掌握完整上下文的个人工作台。

在此之后，Atlas、Opera Neon 和 Gemini in Chrome 继续加了一把火。Opera 至今仍把 Neon 定义为“built to act”，Google 则让 Gemini 代办订餐、预订和购物。AI 浏览器的卖点不再是帮人看网页，而是替人操作网页、办事。

国内也很快跟了上来。美团旗下光年之外团队推出的 Tabbit，直接将自己定义为 AI 原生浏览器，可以引用标签页、截图和本地文件，也能让 Agent 自主阅读页面、填写表单和跨网站执行任务。这些变化，都在把浏览器改造成 Agent 的工作空间。

这套逻辑并没有错。浏览器里装着一块高度兼容的互联网，几乎所有线上服务都（国内互联网巨头平台比较例外）能在这里被打开。更重要的是，AI 浏览器还保留了用户熟悉的标签页、地址栏和窗口。用户可以看着 Agent 一步步工作，在付款、发送和提交前接管。

但浏览器同时也是一种沉重的用户习惯。StatCounter 的数据显示，今年 6 月 Chrome 仍占全球浏览器市场的 69.65%。对于大部分人来说，换掉 Chrome 或 Safari，意味着重新迁移书签、密码、插件和登录状态。AI 浏览器必须证明自己的价值远高于一个插件，才能说服用户搬家。

Agent 平台则是直接掀桌了。

用户要完成的是找资料、订酒店、整理文件或者提交一份表格，并不在意为此打开哪款新浏览器。只要 Agent 能在 ChatGPT、Codex 或操作系统中交付结果，从哪里启动浏览器就不重要。能调用 API 就调用 API，网站提供 MCP 等标准接口就直接调用工具，实在没有机器通道，再打开网页识别界面、模拟点击。

Atlas 关闭前，Codex 桌面端本身就已经内置浏览器。Agent 可以在任务需要时打开网页、跨标签操作、下载文件，也可以调用用户已有登录状态的 Chrome。后来 Codex 与 ChatGPT 合并成新的桌面应用，浏览器继续作为 Work 和 Codex 共用的任务能力存在。

这个顺序很能说明问题。浏览器最自然的位置是在 Agent 平台内部，按需出现，而不是反过来用一整款浏览器包住 Agent。

国内，腾讯WorkBuddy、字节豆包工作、阿里千问办公都把交付文档、表格、PPT、网页或项目结果放在前台，搜索网络、读取文件和调用工具则被藏进执行过程，豆包工作、千问办公还能直接操作网页。

对用户来说，重要的是拿到结果，而不是陪着它打开了多少网页。AI 浏览器减少了浏览网页的劳动，Agent 则开始减少“浏览网页”本身。

03

独立浏览器不会消失，

但正在“退居二线”

Cloudflare 在今年 7 月发布了一份报告，指出互联网流量中，非人类流量首次超过 50%。但这个数字不能直接理解为 AI Agent 已经制造了互联网一半流量，其中还包括训练爬虫、搜索爬虫和其他自动化程序。但 Cloudflare 同时还披露，截至 6 月，AI 训练已经占其识别到的爬虫请求的 52%，混合搜索、Agent 与训练用途的爬虫超过 36%。

更激进的判断来自 Cloudflare CFO Thomas Seifert。他预计，未来五年机器流量可能达到人类流量的 1000 倍。这当然只是一项预测，而且 Seifert 也承认自己的判断可能有偏差。但它指向的趋势已经出现：互联网正在迎来数量更多、频率更高的机器访问者。

马斯克也非常认可这个变化。

图片来源：X

但当面向人的 AI 浏览器开始退潮，面向 Agent 的浏览器反而出现了。Cloudflare 已经将 Browser Rendering 改名为 Browser Run——一款为面向 Agent 的云端浏览器，可以在云端启动无头 Chrome，让 Agent 操作网页、抓取内容、生成截图，并支持记录、回放和人工接管。

这个浏览器不需要面向人类的 GUI 设计，一次任务结束后就被销毁，却能在云端被成千上万次地唤醒。

原因在于今天的互联网仍然是为人设计的。大量网站没有 API，更谈不上 MCP，登录、验证码、动态页面和支付流程都依赖图形界面。Agent 想要操作这部分旧互联网，仍然需要一个能完整运行网页的兼容层。

但网页点击不是最理想的机器接口。按钮会换位置，页面会改版，弹窗和验证码随时可能打断任务。Cloudflare 在 Browser Run 中加入 WebMCP，就是让网站直接向 Agent 暴露结构化工具，替代“看截图—找按钮—点击”交互循环。

本质上，这是互联网开始为 AI Agent 改造。过去的网站默认访问者是人，所以用页面、按钮和表单组织服务。接下来，越来越多网站会提供机器可读的内容、身份、权限和交易接口，让 Agent 不必模仿鼠标点击，也能搜索、比较和下单。网页不会立刻消失，但会多出一个面向机器的入口。

另一方面，浏览器开始后台化。过去用户自己搜索、打开十个网页、比较信息、填写表格。现在用户只需向 Agent 交代目标，网页浏览和交互被挪到后台。Agent 可能连续启动多个浏览器实例，也可能改走 API 或 MCP，用户只在结果或关键确认出现时短暂看见网页。

比如豆包工作就在交互界面融入了浏览器，直接用于内容呈现与用户交互：

（图源：豆包工作，由雷科技生成）

用户使用 Agent 越多，亲自打开浏览器的必要就越低。浏览器依然负责兼容没有机器接口的旧网页，却从人类进入互联网的窗口，退到了 Agent 操作互联网的运行环境。

04

浏览器不会死，

但用户会越来越少打开它

至少现在，面对很多桌面端的任务，我们还不能离开浏览器。

除了 Agent 的能力、体验仍然需要继续改进，安全也是一个限制。Google 将间接提示注入称为所有 Agent 浏览器面对的首要新威胁，OpenAI 在 Atlas 存续期间也持续加固同类防御。不过，权限隔离、身份授权、关键操作确认和任务审计都会继续成熟，今天的风险说明现在的 Agent 还不够可靠。

但技术在进步，尤其 AI 技术的进步速度更是一次又一次超乎很多人的预期。

图片来源：Anthropic

Agent 每接手一部分网页操作，人类就少一次搜索、跳转、比较和填写。这个过程不会在某一天突然完成，更可能以一种不易察觉的方式发生：先是不再亲自翻十个网页，接着很好主动打开网站，最后都只在核对结果时偶尔出现。

现在来看，AI 浏览器可能很难成为一个长期独立的产品类别。对少数研究、开发和专业用户来说，一款能够理解所有标签页、允许随时监督 Agent 的浏览器，仍然会是一个不错的 AI 工作台。

但对大部分普通用户来说，浏览器的使用价值却会被逐步削减，或许它不会从电脑上消失，但它会更多内置在AI应用和Agent平台中，用户亲自动手的打开频率、停留时间和承担任务都会越来越少。

浏览器厂商也可继续向 Agent 平台转型，承接任务、连接工具、管理身份与权限，并为用户保留接管窗口。只是发展到那一步，它还是不是应该叫“浏览器”，就很难说了。
